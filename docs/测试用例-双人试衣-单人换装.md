# 多人换装测试用例 A · 只让一人换装（10 格）· v2

> 目的：验证"**只让一个角色换装**"能否救回服饰归属。
> 上游：`docs/测试用例-双人试衣-服装店.md`（v1，两人都换装 → 全崩）
> 依据：`docs/批量漫画-路由与IR契约-草稿.md` §6.4
> 渠道：silver（无气泡，`--silver-only`）

---

## 一、与 v1 的唯一变量

| | v1（崩） | **v2（本用例）** |
|---|---|---|
| 角色1（黑发·高） | 逐格换装 | 逐格换装（不变） |
| 角色2（粉发·小） | **逐格换装** | **服饰冻结 → 进固定块** |
| 每格动态段的服饰组数 | 2 组 | **1 组** |

只改了这一处。其他（发色锚点、身高差、场景、光线、景别）全部保持不变，这样出问题能直接归因到"换装组数"。

**本用例不叠加"锚点相邻"技巧**——那是方案 B。A 要单独测，才能知道"减半歧义"本身够不够。

---

## 二、为什么这样能救

1. **角色2 的服饰进了固定块，而且紧贴她的外观标签**：
   `pink_hair, twintails, ..., petite, pink_sweater, plaid_skirt`
   ——她在固定块里就是"外观 + 衣服"绑死的一整块，模型不用再猜她穿什么。
2. **每格动态段只剩角色1 一套衣服**：模型已经知道"粉毛衣+格纹裙 = 粉发那个"，
   剩下没归属的服饰标签（红裙/黄裙/白裙）自然落到角色1 身上。
3. 上一轮"牵手拥抱"能过的本质就是"服饰共有、无需绑定"；本用例把角色2 的服饰变成"已知常量"，
   等于把"两组未知"降成"一组未知"——这是最接近"共有"的可行形态。

## 六、观察点

1. **角色2 是否全程原装**：粉毛衣+格纹裙有没有漂移（这是本用例最该稳的地方）。
2. **角色1 的服饰是否按序切换**：原装→红→黄→白，有没有跳格或串色。
3. **角色1 的裙子有没有跑到角色2 身上**（v1 的核心病灶，重点看）。
4. **身份锚点**：发色、发型、身高差是否稳定（v1 里角色1 长出过双马尾）。
5. **换装动作**：第 2/3/5/7 格的"拿衣服"过程感。

## 九、v2（A方案）实测结果（2026-10-08）：仍在串，但暴露关键规律

角色2 的服饰**没有守住**（一路从粉毛衣 → 白衬衫 → 牛仔外套 → 红裙 → 黄裙 → 白裙）；
而角色1 试的裙子（红/黄/白）**几乎全部落在角色2 身上**。

| # | 期望 角色1 | 实际 角色1（黑发） | 实际 角色2（粉发） | 判定 |
|---|---|---|---|---|
| 1 | 牛仔+黑裙 | 牛仔+白衬衫+格纹裙 | 粉毛衣+格纹裙 ✓ | 角色2 正确；角色1 裙色错 |
| 2 | 牛仔+黑裙(拿红裙) | 牛仔+白衬衫+格纹裙(拿**粉毛衣**) | 白衬衫+格纹裙(拿**红裙**) | 角色2 漂移 + 拿的东西互换 |
| 3 | 同上 | 白衬衫+红围裙(双马尾) | **牛仔外套+白衬衫+黑裙** | 角色1 整套跑到角色2 |
| 4 | 红裙 | 藏青西装外套+格纹裙 | **红裙** | 红裙落到角色2 |
| 5 | 红裙(拿黄裙) | 藏青外套+格纹裙(拿红裙) | **黄裙**+围巾 | 黄裙落到角色2 |
| 6 | 黄裙 | 藏青T恤+格纹裙 | **黄裙** | 黄裙仍在角色2 |
| 7 | 黄裙(拿白裙) | **粉开衫**+格纹裙(拿粉毛衣) | 黄裙+白围裙 | 角色2 的粉毛衣跑到角色1 |
| 8 | 白裙 | 藏青西装+格纹裙 | **白裙** | 白裙落到角色2 |
| 9 | 白裙 | 藏青西装+格纹裙(拿粉物) | **白裙** | 同上 |
| 10 | 白裙 | 藏青背心+白衬衫+格纹裙 | **粉开衫+白裙** | 同上 |

### 关键发现：动态服饰会绑定到"紧邻其前的那个角色块"

组装顺序是 `全局 + 角色1 + 角色2 + 动态`。动态段里装的是**角色1 的服饰**，
但它**紧跟在角色2 的块后面**——模型把这段新服饰**吸到了离它最近的上一块角色（角色2）身上**。
所以"试穿的裙子"几乎每次都落在角色2。

**这不是颜色/语义偏好，是位置效应**：谁挨着动态段，谁就"吃掉"动态里的衣服。

这条规律同时解释了 v1（两人都换装）为什么乱：动态段混了两人的服饰，而它只挨着最后一块（角色2），
角色1 的服饰没有"归属位置"，只能随机飘。

### 修法：换装的角色必须放在最后（紧邻动态段）

- 本场景（只有角色1 换装）→ 组装顺序改为 `全局 + 角色2(冻结) + 角色1(换装) + 动态[角色1服饰]`。
- 通用规则：**动态段里描述的服饰属于谁，谁的块就必须排在最后。**
- 这是零成本的改动（只调顺序），直击本轮发现的 bug，**下一步先测它**。

## 十一、v3（重排）实测结果（2026-10-08）：有效，9/10

**重排生效**：换装者置后之后，服饰归属基本稳住，10 格中 9 格正确。位置规则确认。

**1 格出问题**：粉发女孩的**双马尾形态漂了**（高低/长短/扎法变了）。

### 根因：固定块里泛化父标签与具体标签并存

```
pink_hair, twintails, low_twintails, hair_ribbon, ...
        ↑ 泛化父标签     ↑ 具体款
```

`twintails` 是父标签，对应训练数据里"所有双马尾形态"的分布。虽然同写了 `low_twintails`，
但**父标签没删**，模型仍有权在整个"双马尾类别"里挑形态 → 个别格漂移。

**同类隐患（都在固定块里）**：

| 现写法 | 问题 | 改法 |
|---|---|---|
| `twintails` + `low_twintails` | 父标签未删 | 只留 `low_twintails` |
| `long_hair` | 泛化（多长？） | `very_long_hair` |
| `hair_ribbon` | 没写颜色 | `red_hair_ribbon` |
| `pink_sweater` | 没写材质/款式 | `pink_cable_knit_sweater` |
| `plaid_skirt` | 没写颜色 | `grey_plaid_skirt` |
| `black_skirt` | 没写款式 | `black_pleated_skirt` |
| `red_dress` / `yellow_dress` / `white_dress` | 只写颜色，款式空 | `red_long_sleeve_dress` / `yellow_sundress` / `white_frilled_dress` |
