## 〇、先厘清四条"入口"（决定走哪条路）

一条消息进到机器人，先过**触发闸**，再进**直达管道**；管道接不了
才退回 **agent 工具循环**；真正入队前还有**两道守卫**。

| 层级 | 位置 | 作用 |
|---|---|---|
| ① 触发闸 | `qq_bot._should_reply()` | 这条消息**要不要理**：黑名单 → 私聊闸/群白名单 → 全局静音 → @ → 关键词 → 全量模式。**私聊只认文本：单发图/裸引用不回**（2026-10-07） |
| ② 直达管道 | `direct_gen.decide()` | 生图/聊天主链路，**一次 LLM 调用封顶** |
| ③ 守卫 | `generate_image._hd_tier_guard` / `_t2i_guard` | 入队前最后两道（**只在 QQ 轮里判**，看的是"本轮原话"） |
| ④ agent 循环 | `agent.run_agent_stream()` | 直达管道返回 `None` 时才兜底（多轮工具调用） |

> **反推闸（`recall_gate`）已于 2026-10-07 删除**。原先它在直达管道之前横插一道：
> 见到「反推/提取提示词/图生文…」这类字眼 + 图，就代码直调识图、模型整轮不参与。
> 用户拍板：「反推闸你就是多此一举…大模型它肯定比你这个硬编码正则匹配要牛逼，
> 有图片都默认走 AI」。唯一保留的硬编码是**裸「提取提示词」+ 自家 HT 图 → 直通
> 账本**（因为落在自家账本上、足够确定），其余一切有图的轮次全部交给 AI。

### 关键：**渠道（skill）由谁定？**（这是本次重写变化最大的地方）

| 渠道类别 | 谁定 | 代码里的位置 |
|---|---|---|
| **默认渠道** | 代码写死 = **`silver`** | `direct_gen._DEFAULT_SKILL` = `generate_image.T2I_DEFAULT_SKILL` = `"silver"` |
| 尺寸档（快档/一档/二档/三档） | **代码**（`_parse_channel` 认死） | `_TIER_MAP` / `_TIER_RE` |
| 画风（clear/soft/gloss/curvy） | **代码**（仅"开头"才认） | `_STYLE_RE` |
| 固定渠道词（`sd`/`krea2`/`qwen`/`nffa`/`nai`/`cunny`/`miao`） | **代码**（`_FIXED_CHAN_MAP`） | `_FIXED_CHAN_RE`（词边界、下划线阻断） |
| **`silver` / `jank`** | **AI 判**（代码**认不出**、故意不硬编码） | 不在 `_FIXED_CHAN_MAP`；由 `_allowed_skills()` 现场扫 `skills/` 目录放行 |

优先级 = **位置**：**开头**点名的固定渠道词优先级最高；句子中间则"最早命中的赢"。

> ⚠️ 注意一个**代码会抢跑**的坑：`_parse_channel()` 会**先扫到档位词**，所以
> `silver 三档` → 代码认成 `ch = hd_3_clear`、把 `silver` 留成提示词内容。
> 详见「三、冲突清单」的第 1 条。

## 三、冲突清单（当前仍存在 / 已解决）

### ✅ 已解决 1（原冲突 1+2）：`渠道词 + 档位词` 并存 —— **严格取最左那个**（**2026-10-07 最终版**）

**病**：`_parse_channel` 只认两类词——`_FIXED_CHAN_RE`（固定渠道）和 `_TIER_RE`
（档位）。`silver`/`jank` 不在任何一类里，于是「silver 三档」时游标落到档位词、
锁成 `hd_3_clear`，把 `silver` 当成**画面内容**丢进 desc。

**中间方案（已废弃）**：曾加过 `_alt_channel(desc)` 上报第二个渠道词、把矛盾摊给
AI 判。用户 2026-10-07 拍板**不要这套兜底**：

> 「思路，你就认第一个就行了，你从左到右。他打 Six 三档，那就走 Six 就行了。
> 如果他说三档 Six，那你直接走三档就行了…如果他给多个渠道词的话，你就看哪一个
> 渠道它是排在第一的」「冲突 2，你就把这个兜底什么 chan_hint 给我去掉，全部交给
> AI 去进行判断就行了…AI 你判不准直接跑默认渠道，保证不会出错。」

**最终方案**（代码最简）：

1. `_parse_channel` 回到 **2 元组** `(skill, desc)`——**严格取从左到右第一个命中的
   渠道/档位词**，不上报、不裁决。
2. 删掉 `_alt_channel()` 及整条 `alt` 管道（`_translate(alt=)` / `_revise(alt=)`）。
3. `chan_hint` 回到单支：「用户开头点名了渠道：**X**，就用它。」
4. 自定义渠道（silver / jank）识别不出**就留在 desc 里**，由 AI 判是不是渠道；
   AI 判不出 → 走默认渠道 silver（保证不出错）。

**最终实测**：

| 输入 | skill | desc |
|---|---|---|
| `silver 三档` | `hd_3_clear` | `silver` ← silver 留正文，交 AI 判 |
| `三档 silver` | `hd_3_clear` | `silver` |
| `nai 三档` | `nai` | `三档` ← nai 排前，固定词赢 |
| `三档 qwen` | `hd_3_clear` | `qwen` ← 档位排前 |
| `三档 gloss 初音未来` | `hd_3_gloss` | `初音未来` |
| `sd 一只猫` | `image_gen_v1` | `一只猫` |

**留过的坑（归档）**：`_alt_channel` 里边界正则的 `\w` **会匹配 CJK** → 必须用
`[0-9A-Za-z]`；英文 tag 流的假阳性（`sd style` 里的 sd）也要跳过。**该函数已删**，
坑随函数消失。

### 🟡 冲突 3：`_hd_tier_guard` 与默认渠道变更的耦合

`_hd_tier_guard` 降级时用的是 `default_skill`——现在传的是 `T2I_DEFAULT_SKILL`（silver）。
以前默认是 `anima_clear`，降级后是动漫档；现在降级会落到 **silver**。
这本身正确（默认渠道确实变了），但降级话术里写的是"已按默认的 silver 出图"——
**用户原来的意图是"别糊"，silver 恰好也能满足**，所以没实际危害，只是要意识到
降级目标随默认渠道漂移。

### 🟡 冲突 4：`silver` 既是渠道名又是发色词

代码侧已经处理：silver **不在** `_FIXED_CHAN_MAP`，所以 `一只银发少女` 不会被
误判成渠道。文案侧（`_MASTER_TEMPLATE` / `_REVISE_TEMPLATE` / 工具描述）都有
明确警告「银发 / silver hair 是画发色」。**但这是靠 AI 自觉**——如果 AI 判错，
用户会看到提示词里被塞进渠道语义。属于**可接受残留**。

### ✅ 已解决 5（原冲突 5）：反推闸与「要词条直通」的判据重叠（**2026-10-07 删闸**）

原来两条正则都在"要提示词"语义空间里：`recall_gate._intent`（反推/提取提示词/
图生文/识图…）和 `direct_gen._PROMPT_ASK_RE`（查看/提取/给我…+提示词/词条）。
用户拍板**整块删掉**：

- `app/recall_gate.py` **删除**（文件 + import + `qq_bot.py` 调用点）；
- `direct_gen._PROMPT_ASK_RE` **删除**；`_PROMPT_BARE_RE` 收窄到**只认裸
  「提取提示词」5 个字**；
- 其余一切「识别图片 / 图生文 / 转化成提示词 / 给我提示词 / 我要这个图的提示词」
  全部交给 AI——用户原话：「你永远无法揣测用户意图…你交给大模型，至少能覆盖
  99%」「反推闸你就是多此一举」。

> **保留的唯一硬编码**：引用**自家带 HT 编号的图** + 说**「提取提示词」** →
> 返回当时真跑的那段提示词（账本直通）。理由：它落在自家账本上，足够确定，
> 不依赖任何意图揣测。这条路同时还有 `recall_image` 工具兜底（AI 自己也能查）。

### ✅ 已解决 6：发图（1.3）不再靠正则猜用户说什么（**2026-10-07 删正则**）

原先 1.3 那批用例（32~40 号）靠 `_DESCRIBE_RE` / `_IMG_GEN_INTENT_RE` /
`_GENERIC_I2I_RE` / `_RUN_THIS_RE` 猜「用户说的是不是某几句话」。用户原话：
「你觉得你能够预测用户他可能会说什么，但这永远不可能…你必须走 AI。所以 1.3
发图这部分，把这一个硬编码给我去掉」。现在**发图 + 指令默认走 AI**：整句交给
`_revise`（引用图）或 `_translate`（自发的图），要垫图由模型在 JSON 里填
`source_image` 决定。

### ✅ 已解决 7：私聊单发图不再提前反推（**2026-10-07**）

原先 `_should_reply` 私聊分支是 `has_content = text or image or quote` ——
一张裸图也算"有内容"，直接触发整轮；再加上 `direct_gen.decide` 里
`if not text and data_urls: return 反推`，于是用户图刚发出来、话还没说完就被
反推。用户原话：「你发张图片，你 AI 就直接反推图片…你根本就不知道用户想要做
什么事情」。现在 **A+B 双保险**：

- **A**：`_should_reply` 私聊分支**只认文本**——裸图 / 裸引用一律不回（图留在
  会话历史里），用户接着发文本的那一轮再把邻近的图带上。
- **B**：`direct_gen.decide` 的裸图分支仍保留（群聊单发图 = 想要词条，用户明确
  要求别动）——但私聊那层已经拦在前面，进不来。

### ✅ 已解决 8：`提示词` 直通收窄到「提取提示词」（**2026-10-07**）

`b570283` 曾把直通放宽成 `_PROMPT_ASK_RE`（动词式）+ `_PROMPT_BARE_RE`（整句

```
给我提示词    -> 走AI                 词条         -> 走AI
查看提示词    -> 走AI                 提示词是什么  -> 走AI
```

### ✅ 已解决 3：引用图 + `silver` 不再跑成 jank

旧根因：`_revise` 里 `skill = channel or data["skill"]`，`channel=None` 时用
`anchor_skill`（账本里那张图当初的渠道 = jank）。现在 `_REVISE_TEMPLATE` 里

### ✅ 已解决 4：图生图的静默降档

`_redraw_capable` 已删——以前一说"图生图"就把非动漫档静默降回默认档，

## 四、使用说明书（面向用户）

### 4.1 一句话上手

**@我（或喊「大大怪」）+ 渠道 + 你想要什么**。不写渠道就**默认走 silver**。

```
三档 女骑士            ← 尺寸档 + 描述
jank 银发初音未来       ← 自定义渠道 + 描述
qwen 水晶城堡          ← 固定渠道 + 描述
一只在海边的少女        ← 不写渠道 = silver
```

### 4.2 渠道总表

| 类别 | 写法 | 说明 |
|---|---|---|
| **默认** | **不写渠道** | **silver**（Anima 系 Turbo，1024×1536，最快） |
| 尺寸档 | `快档`/`一档`、`二档`、`三档` | 越往后越清晰越慢；后面可直接跟描述 |
| 画风 | `clear`/`soft`/`gloss`/`curvy` | **接在档位后**；只说画风（没说档）= 动漫最小档 |
| 组合 | `二档 gloss 少女` | 尺寸档 × 画风 |
| 自定义 | `silver`、`jank` | 点名才用；**文生图专用，没有图生图骨架** |
| 固定 | `sd`（可一次多张，` --- ` 分隔）、`krea2`、`qwen`、`nffa`、`cunny`、`miao`、`nai` | 各有特性，见 `/更多渠道` |

### 4.3 引用玩法（最容易踩坑的部分）

| 你想干什么 | 怎么写 |
|---|---|
| **要这张图当初的提示词** | 引用带编号的图/回执 + 发「提示词 / 给我提示词 / 提取提示词」（**零调用，最快**） |
| **照着这张改，重画一张** | 引用图 + 说需求（「把头发改成银色」）→ 沿用原渠道改词重画 |
| **只改画面里那一处** | 引用图 + `qwen 图生图 + 怎么改`（慢，1~2 分钟） |
| **只 @我**（不写字） | 返回这张图的反推提示词 |
| **引用图 + 档位**（如「三档」） | 反推后直接生成 |
| **引用出图回执 + 再来一张** | 同提示词换种子重跑 |

> ⚠️ **引用一张图本身永远不是"垫图"要求**。想只改一处，必须**明说
> 「qwen 图生图 + 改什么」**；只说改动内容（「把衣服换成jk」）会**改提示词重画一张**。

### 4.4 看图 / 反推

| 写法 | 行为 |
|---|---|
| `反推` / `提取提示词` / `识别一下这张图`（**配图**） | 代码直调识图，返回可用的英文提示词 |
| `这画的是什么`（配图） | 返回一段中文画面描述 |

### 4.5 随机口令

`今日老婆` ｜ `随机萝莉` / `随机兽耳` / `随机女仆` — 零门槛，直接出图（走默认渠道）。

### 4.6 管理页可改的两段附言（2026-10-06 新增）

| 键 | 位置 | 三态语义 |
|---|---|---|
| `receipt_note` | 提交回执（「任务已提交…」+「当前渠道：X」之后） | 没设过 = 内置默认；**空串 = 不要这段**；其余 = 自定义（≤400 字） |
| `caption_note` | 出图 caption（`编号 · 分辨率 · 渠道 · seed` 之后） | 同上 |
