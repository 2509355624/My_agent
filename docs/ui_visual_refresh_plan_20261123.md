# 视觉与交互改造方案（2026-11-23）

## 目标

把几个页面从「功能清单」改成「任务路径」：默认只看结果，按页反馈，AI 自己改，再重画。
视觉走正式产品方向：简洁、留白、少字、明暗双主题；不堆参数，不花哨。

## GitHub 现成项目调研（可借鉴的点）

| 项目 | 定位 | 我们借鉴什么 |
| --- | --- | --- |
| `AUTOMATIC1111/stable-diffusion-webui` | 表单式老牌 WebUI，扩展生态最大 | 参数分组方式；**不学**一屏平铺 |
| `Comfy-Org/ComfyUI`（旧地址 `comfyanonymous/ComfyUI`） | 节点式引擎/后端 | 继续当后端事实源；节点图不给普通用户看 |
| `lllyasviel/Fooocus` | 极简：提示词 + 风格 + 生成 | 默认值兜底，少控件也能出好图 |
| `invoke-ai/InvokeAI` | 统一画布、局部重绘 | 「在结果上直接改」的交互范式 |
| `mcmonkeyprojects/SwarmUI` | 简洁前台 + ComfyUI 后台，多用户/队列 | 简单模式 / 专家模式分层，最接近我们的架构 |
| `huggingface/diffusers` | 工程库，不是成品 UI | 服务化、API 化的做事方式 |

结论：**不照搬任何一家**。走 Fooocus 的少控件 + SwarmUI 的分层 + InvokeAI 的「在结果上改」。

## 设计原则

1. **结果优先**：普通用户默认看到图，不看到剧本和提示词。
2. **三层信息**：主路径（生成 → 看结果 → 反馈重画）；按需层（每页反馈、参数）；专家层（剧本 / 提示词 / LoRA / 布局）。
3. **少字**：按钮只写动作，说明最多一句，能用状态/图形表达就不写段落。
4. **明暗双主题**：一套语义色变量；跟随系统偏好，手动切换后记住；看图器保持黑底以免干扰图片。
5. **统一组件**：按钮、卡片、tab、空态、加载态、错误态四处共用一套规则。

## 分期落地

### P0 · 画廊样板（本轮已做）

- 加 `data-theme` 语义色变量，白天/黑夜一键切换并记住选择，首屏无闪色。
- 说明压成一行，整理类入口标清用途，不新增文字墙。
- 原有 tab、按钮、接口、守卫测试全部保持。

### P1 · 漫画工作台 / moss 台：结果优先（下一步）

新主路径只有三步：**写一句话剧情 → 生成并出图 → 看每页结果并反馈**。

- 输入只要剧情/大纲；剧本由 AI 生成后默认收进「专家模式」，不再占主屏。
- 结果区按页展示大图卡片，每页只留：页码、状态、重画、一个反馈输入框。
- 反馈输入框写「这页哪里不对，直接说」；提交后把**该页当前 layout / 提示词 / 角色外形 / 用户反馈**交给补正 AI，产出修订页，**只重画这一页**。
- 顶部只保留：返回、任务、整体进度、主题切换。LoRA / 步长 / 画风等收进专家层。

### P2 · 管理页 / 状态页

沿用 P0 的主题变量与组件规则；配置区改成按任务组织的卡片，不再按后端字段名平铺。

### P3 · 沉淀设计系统

把四页重复的 CSS 变量、按钮、卡片、空态抽成共享片段，避免每页各写一套后再次跑偏。

## 验收标准

- 首屏就能看到结果，不需要滚动找主按钮。
- 普通用户三次点击内完成「生成 → 反馈 → 重画」。
- 剧本 / 提示词默认不可见，专家模式一键展开。
- 明暗主题切换无闪屏、刷新后保持。
- 不丢任何现有功能 id / 接口；结构守卫测试全绿。
