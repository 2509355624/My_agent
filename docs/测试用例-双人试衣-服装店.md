# 多人换装测试用例 · 双女生 · 服装店试衣（10 格）· v1

> 目的：验证**多人 + 逐格换装**下，两人各自的服饰切换是否正确、会不会串色/串型。
> 依据：`docs/批量漫画-路由与IR契约-草稿.md` §5.2 / §6.2 / §6.4
> 渠道：silver（无气泡，`--silver-only`）
> 这是契约标注的**最高风险场景**（多人都要换装），本用例就是来压它的。

---

## 一、本场景的核心难点

单人换装没问题，多人换装会炸，根因有两个：

1. **booru 标签是全局池，不绑定到具体某人**——写 `red_dress` 时模型不知道是角色1 还是角色2 穿的。
2. **服饰留空 = 模型自由发挥**——某格若没写某人当前穿什么，模型会自己补，往往从另一人身上串过来。

所以本场景的服饰**不能进固定块**（它要变），必须**逐格写进动态段**。这就是你说的：
动态段要同时承载"**该格固定的当前服饰**"和"**逐格切换的服饰变化**"。

---

## 二、服饰的写法规则（本用例立的新规则）

### 规则 1：服饰三件套，每格必写

每一格的动态段，服饰部分**必须**包含这四项，缺一项判不合格：

| 项 | 内容 | 例 |
|---|---|---|
| ① 角色1 当前服饰 | 写全：类型 + 颜色 | `denim_jacket, white_shirt, black_skirt` |
| ② 角色2 当前服饰 | 同上 | `pink_sweater, plaid_skirt` |
| ③ 换装动作（若有换装） | 拿/换的动作 | `holding_clothes, red_dress` |
| ④ 不变的服饰件 | 放固定块，动态不重复 | `white_socks`（全局） |

### 规则 2：顺序冻结

角色1 的服饰标签**恒在**角色2 之前。顺序一变，模型可能把两人的衣服对调。
（booru 无法精确绑定，顺序是我们唯一的弱暗示。）

### 规则 3：类型错开

两人尽量用**不同服装类型**（一个连衣裙、一个上衣+裙），颜色也错开。
类型差异是给模型的第二重区分线索——光靠颜色（`red_dress` vs `yellow_dress`）它容易搞混。

### 规则 4：换装动作要写出来

"正在换"的过程靠动作标签传达：`holding_clothes` / `holding_dress` / `fitting_room` / `curtain` / `mirror`。
不写动作，模型只会画"穿着站着"，看不出"在试衣"。

### 规则 5：不变的服饰件进固定块

袜子、发饰这类全程不换的 → 写进固定块（`white_socks` 在全局、`hair_ribbon` 在角色2）。
动态段**不许重复**它们（重复 = 双写漂移）。

## 六、观察点

1. **服饰归属**：角色1 的黑发女孩是不是一直穿"她该穿的那套"？角色2 呢？有没有串色（红裙穿到粉发身上）？
2. **切换时机**：第 4 格角色1 才换好、第 6 格角色2 才换好——节拍有没有错位？
3. **切换动作**：第 2/3/5 格有没有画出"拿衣服/准备试穿"的过程感？
4. **不变件**：`white_socks`、`hair_ribbon` 是否全程稳定？
5. **身高差**：`height_difference` 是否守住（这是上一轮补的规则）。
6. **发色/发型**：两人锚点是否稳定。

---

## 七、如果失败，怎么归因

| 现象 | 指向 |
|---|---|
| 两人衣服对调 | 顺序被模型忽略 → 强化"类型错开"（规则3） |
| 某格出现"第三套"没人穿的衣服 | 动态段服饰写漏 → 补全规则1 |
| 颜色对了、类型错了（红裙变红上衣） | 服饰类型标签不够具体 → 写全 `red_dress` 而非 `red` |
| 服饰在格与格之间随机跳 | 某格动态段没写服饰 → 回填 |
| 袜子/发饰漂移 | 不变件没进固定块，或动态段重复写了 |

## 八、待核实

- `holding_clothes` / `holding_dress` / `fitting_room` / `looking_at_mirror` 是否都是 danbooru 标准标签，
  若某几个不是，模型可能忽略（参考上一轮 `medium_shot` 的情况）。跑完看哪几个没生效，再换写法。
- `striped_sweater` 两人共用一条标签（同款），靠 `black_skirt` / `white_skirt` 区分——这是**故意的最小区分**，
  用来测"同款不同色"时模型还能不能分对人。

## 九、v1 实测结果（2026-10-08）：服饰归属崩溃

10 格**全部**出现服饰错位，连"原装"的第 1 格都错。

| # | 期望 角色1 / 角色2 | 实际 黑发 / 粉发 | 判定 |
|---|---|---|---|
| 1 | 牛仔+黑裙 / 粉毛衣+格纹裙 | 粉毛衣+黑裙 / 牛仔+格纹裙 | 上衣互换 |
| 2 | 牛仔+黑裙(拿红裙) / 粉毛衣+格纹裙 | 牛仔+格纹裙(拿粉毛衣) / 红裙 | 全错 |
| 3 | 同上（试衣间） | 牛仔+格纹裙(拿粉毛衣) / 红裙 | 全错 |
| 4 | 红裙 / 粉毛衣+格纹裙 | 红裙 / 粉毛衣+格纹裙 | **衣服对**，但黑发变娇小+双马尾、粉发变高 |
| 5 | 红裙(拿黄裙) / 粉毛衣+格纹裙 | 黑毛衣+红格裙(拿粉毛衣) / 黄裙 | 全错 |
| 6 | 红裙 / 黄裙 | 红裙(粉发) / 黄裙(黑发) | 互换 |
| 7 | 白裙 / 蓝裙 | 白裙(粉发) / 蓝裙(黑发) | 互换 |
| 8 | 白裙 / 蓝裙 | 白裙(粉发) / 蓝裙(黑发) | 互换 |
| 9 | 条纹毛衣+黑裙 / 条纹毛衣+白裙 | 蓝条纹毛衣+白裙 / 背心+黑裙 | 全错 |
| 10 | 条纹毛衣+黑裙 / 条纹毛衣+白裙 | 藏青开衫+黑裙 / 棕毛衣+白裙 | 全错 |

### 根因：booru 标签是全局池，服饰无法绑定到人

- 上一轮"牵手拥抱"9/10 成功，是因为两人**穿同一套校服**——服饰是**共有**的，根本不需要绑定。
- 本轮两人**服饰不同**，"绑定需求"第一次出现，模型直接崩。**不是写法问题，是 booru 标签体系的固有天花板。**
- **顺序弱暗示无效**：我们已把角色1 的服饰排在角色2 之前，模型照样对调——"靠标签顺序绑定"这个假设不成立。
- 第 4 格是唯一衣服对的，但同格把两人的**身高/发型**互换了（黑发变娇小+双马尾）→ 模型是在"整体重分配角色属性包"，不是按人绑定。
- 附带损伤：黑发女孩在第 2/4/6 格长出双马尾（角色2 的发型），体型也互换。

### 修法（待验证，按可行性排序）

1. **锚点+服饰相邻**（首选）：每格把服饰**紧贴该角色的锚点**写——`black_hair, red_dress` / `pink_hair, yellow_dress`。
   只重复"锚点"这一个标签（不是整块外观），既给模型绑定线索，又不算大范围双写。
2. **只让一人换装**：配角服饰进固定块，主角服饰逐格。把"两组不同服饰"降成"一组变、一组不变"，绑定歧义直接减半。
3. **闺蜜装**：两人同款 → 服饰又变"共有" → 绑定需求消失（但本用例第 9–10 格说明：**同款只要颜色不同仍会崩**）。
4. **路由层降级**：命中"多人 + 换装"就提示用户，建议拆成多个单人任务。
