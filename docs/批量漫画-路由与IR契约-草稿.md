## 0. 触发形态

用户侧：

```
大大怪，<画风>漫画，<数量>，<需求描述>
```

例：`大大怪，silver漫画，20个，妹妹收到新衣服后一件件试穿`

解析成四元组 + 可选素材：

| 片段 | 例 | 用途 |
|---|---|---|
| 触发词 | 大大怪 | 唤醒机器人 |
| 画风 | silver | 决定渲染渠道 |
| 数量 | 20 | 决定动态段数 N；**默认阈值 10** |
| 剧情 | 妹妹收到新衣服后一件件试穿 | 喂给编剧模型 |
| 素材（可选） | 引用的图 | 提外观 → 固定块 |

实测耗时：**10 张 ≈ 50–60 秒，20 张 ≈ 100 秒**。默认 N = 10；超出 10 张的处理策略见 §10。

## 1. 关键词路由表

**路由权归意图关键词，"带图"只是素材标记，不参与路由。**

| 优先级 | 命中条件 | 分支 | 图片的角色 |
|---|---|---|---|
| 1 | 命中漫画词（`漫画` / `silver漫画` / `qwen漫画` …） | **漫画流水线** | 角色参考素材（走"提外观"识图） |
| 2 | 命中出图 / 识图词（`qwen` / `silver` / `出图` / `识图` …） | 出图直出 | 识图出词 |
| 3 | 本轮带图，且无上述词 | 识图直出 | 识图出词 |
| 4 | 都不命中 | 主人设 | — |

要点：

- 漫画词优先级最高；命中后**不因"带图"被识图抢走**。
- 命中漫画词时，图片改走"提外观"识图（§2），不再触发"识图直出"。

## 2. 两套识图提示词

同一张图，两条路要的产物不同，必须分开——这是本次的核心改动。

| | 出词版（现有） | 提外观版（新增 · 漫画专用） |
|---|---|---|
| 触发 | 出图 / 识图直出 | 漫画词 + 带图 |
| 输出 | 一段可直接出图的完整 prompt | **结构化外观标签**（只回答"这个人是谁"） |
| 用途 | 原样发用户 / 直接出图 | 当固定块，逐字复用 N 遍 |
| 禁止 | — | 不许写动作 / 表情 / 场景 / 光线 / 构图 / 质量词 |

提外观版输出格式（建议）：

```
##外观标签
1girl, solo, long_hair, black_hair, twin_tails, blue_eyes, petite, pale_skin

##分组
发型：长黑发 / 整齐双马尾
瞳色：蓝色大眼
体型：娇小 / 肤色偏白
服饰：（有明显服装才写，否则留空）
```

- `##外观标签` 直接当固定块，**必须是 danbooru 标签形态**（见 §4）；`##分组` 只供用户扫一眼确认，不进 prompt。
- 服饰是否进固定块，交给编剧的"边界判定"（§5 / §6）决定，识图阶段只如实描述、不预判。
- 图中是多人时，`##外观标签` 按角色分块输出（见 §5.2），每块一个唯一锚点。

## 3. 流水线顺序

```
用户消息
 └─ 命中漫画词
      ├─ 带图？ ─是→ 提外观识图 ─→ 外观标签 ┐
      │                                      ├→ 编剧模型（写剧本 + 边界判定）
      └─ 无图 ───────────────────────────────┘
                                             ↓
                                     IR（固定块 + 动态块 × N）
                                             ↓
                                     后端解析 → 组装 → 批量生成
                                             ↓
                                     一次性返回连续漫画
```

注意顺序：**带图时识图在前、编剧在后**。编剧要建立在"外观标签已就位"的前提上。

## 4. 标签形态（硬性）

所有**进入 prompt** 的文本，一律是 **danbooru 风格的英文标签短语**：

- 全小写；多词用下划线连接（`twin_tails`，不是 `twin tails`）；
- 逗号分隔的标签串，**不是句子**——不带冠词（a / the）、不带动词变位、不带标点句读；
- 不含任何中文字符。

**为什么是硬性**：booru 标签是渲染模型的训练词汇表。写成自然语言或中文，模型会"自由发挥"，标签直接失效——画面跑偏、角色漂移，正是你说的"会出问题"。

适用范围（三处都要）：

| 位置 | 要求 |
|---|---|
| 提外观版 `##外观标签` | danbooru 标签 |
| 编剧 `##固定部分` | danbooru 标签 |
| 编剧 `##动态部分` | danbooru 标签 |

例外：`##元数据` 不进 prompt，可以中文；`##分组`（识图给人看的确认项）可以中文。

**校验层**：正文块里出现中文 / 句号 / 冠词 / 大写 → 判不合格，回炉。

### 4.1 具体化原则（禁止类别泛指）· 硬性

> 来源：2026-10-08 实测。用户观察：写"休闲服"这种类别词不行，必须写具体单品；双马尾也必须写清是哪一种双马尾。

**任何进 prompt 的服饰 / 发型标签，必须是"可辨识的具体单品或具体样式"，不能用类别泛指。**

| 禁止（泛化） | 换成（具体） |
|---|---|
| `casual_clothes`、`clothes`、`outfit` | `blue_denim_jacket, white_t-shirt, black_pleated_skirt` |
| `dress` | `red_pinafore_dress` / `white_frilled_dress` |
| `skirt` | `black_plaid_skirt`（颜色 + 花纹 + 单品） |
| `sweater` | `pink_cable_knit_sweater` |
| `shoes` | `brown_loafers` / `white_sneakers` |
| `twintails`（父标签，太泛） | `low_twintails` / `high_twintails` / `short_twintails` |
| `long_hair` | `very_long_hair` / `hair_past_waist` |
| `hair_ribbon` | `red_hair_ribbon`（颜色 + 位置） |

两条硬规则：

1. **颜色 / 款式要写全**：单品名之外，颜色（+花纹/材质）必须显式写。
2. **删掉泛化的父标签**：写了 `low_twintails` 就**不要**再写 `twintails`——父标签会让模型在"整个类别"里自由挑一个形态。
   （同理：写了 `black_plaid_skirt` 就不要只写 `skirt`。）

**为什么是硬性**：booru 是渲染模型的训练词汇表。泛化词在训练数据里对应"整个类别"的图像分布，模型只能**随机挑一个具体形态**；
具体词才收敛到唯一形态。这直接解释了"双马尾每格长得不一样"和"裙子款式乱跳"。

**校验层（新增）**：正文块里出现上表左列的泛化词 → 判不合格，回炉要求补全。

## 5. IR 契约（编剧产物）

编剧模型按固定格式输出，后端直接解析。

### 5.1 单人

```
##元数据
数量: 10 | 画风: silver | 场景: 更衣 | 人数: 1 | 边界: 服饰→动态

##固定部分
1girl, solo, blue_hair, twin_tails, school_uniform

##动态部分
---
receiving_parcel, surprised, genkan, warm_light
---
unwrapping, curious, living_room, afternoon_light
---
...
```

### 5.2 多人（≥2 人）

固定部分从"一段标签串"升级成"分层块"——因为 **booru 标签是全局池，不绑定到具体某个人**：

```
##元数据
数量: 10 | 画风: silver | 场景: 更衣 | 人数: 2 | 边界: 服饰→动态

##固定部分
##全局
2girls, multiple_girls, indoors
##角色1
blue_hair, twin_tails, school_uniform
##角色2
red_hair, ponytail, glasses

##动态部分
---
handing_box, surprised, from_side
---
...
```

组装：第 i 格最终 prompt = `全局 + 角色1 + 角色2 + 动态[i]`

多人硬规则：

1. **锚点唯一且互斥**：每个角色块必须有一个唯一锚点，各角色锚点**互不相同**，而且必须**互斥**。
   - **发色是可靠锚点**：`black_hair` / `pink_hair` 天然互斥；
   - **发型不可靠**：`long_hair` 和 `twintails` 不互斥——双马尾的人也可以是长发，模型会把 `twintails` 套到长发角色身上。
   - 锚点重复或非互斥 = 模型无法区分 = 必然串味。
2. **顺序冻结**：角色块之间的顺序在全部 N 格里不变（角色1 恒在前）。顺序一变，模型可能把两人的属性对调。
3. **删掉 `solo`**：单人契约固定开头是 `1girl, solo`；两人场景里 `solo` 与 `2girls` 直接打架，必须删。**人数标签只写在 `##全局` 块**。
4. **动态段只写互动**：不许重复任何角色块的外观标签；关系用互动标签表达（`handing_box` / `holding_hands` / `hugging` / `looking_at_each_other`）。**互相看用 `looking_at_each_other`，单向看才用 `looking_at_another`**（后者是单向标签）。方位在 booru 里无法可靠绑定，只能靠标签顺序弱暗示（角色1 的标签排在前）。**不要试图用标签精确指定"谁的颜色"——booru 做不到，只会徒增冲突。**
5. **人数上限**：1 人最稳，2 人可控，**≥3 人角色一致性明显下降** → 路由层就提示用户，或强制拆成多格。
6. **可选增强**：若角色是知名角色，允许用角色级 danbooru 标签（如 `hatsune_miku`）替代整块外观标签——这类标签自带外观，串味最低。OC 没有对应标签，只能靠上面的锚点规则。
7. **身高差必须显式声明**：`tall_female` / `petite` 是**对比型**标签，本身不带绝对身高（`tall_female` 的 wiki 要求"被画得**与他人对比显得高**"才成立）。只靠它们，**对称构图**（并排站立、同基线、正面中景，如 `park, tree, day, medium_shot`）会把两人抹平成一样高。多人固定块必须加**关系型**标签 `height_difference`（更强用 `size_difference`）进 `##全局`，给出对比语境——它全程不变，属"冻结"。

### 5.3 通用规则（单 / 多人都适用）

- `##固定部分` = 跨 N 格不变的标签，**逐字冻结**（顺序、用词都不许变）。
- `##动态部分` = N 段，每段只写**相对固定块的增量**；禁止重复固定块已有属性（防双写漂移）。
- 段数必须等于 N。
- **边界判定**（什么进固定）：这 N 格里不变的 → 固定；随剧情变的 → 动态。
  - 例 A「下课日常」：服饰进固定。
  - 例 B「收到新衣去换装」：服饰进动态。

> 对照现状：`comics/C20261007-07/script.md` 里 `1girl, solo, blue hair, twin_tails, school_uniform`
> 在 7 格中逐字重复——这一段就是该被抽走的 `##固定部分`。

## 6. 属性归属（不留空原则）

单人测试很稳、多人时出问题，根因是**属性"留空"**：某个属性既不在 `##固定部分`，也没在 `##动态部分` 被提到，模型就自由发挥。多人时这类空缺往往不是凭空补，而是**从另一个角色身上串过来**——所以单人看不出来、多人就炸。

**核心规则：属性三态，不许留空。**

每个属性必须落在下面三态之一：

| 态 | 含义 | 归属 |
|---|---|---|
| **冻结** | 全程 N 格不变 | 写进 `##固定部分`，逐字冻结 |
| **逐格声明** | 每格会变，或"不写就会乱" | **每一格** `##动态部分` 都必须写当前值 |
| **自由** | 写不写都无所谓 | 可省 |

"忘了写"不是一种态——它就是漂移的来源。

### 6.1 归属分类表

| 属性 | 默认归属 | 缺了会怎样 |
|---|---|---|
| 人数 / 性别 | **冻结（必填）** | 人数漂移 |
| 发色 | **冻结（必填）** | 换人 |
| 发型 | **冻结（必填）** | 换人 |
| 瞳色 | **冻结（必填）** | 换人 |
| 体型 | **冻结（必填）** | 忽大忽小、比例漂移 |
| 身高差（多人） | **冻结（必填）** | 两人被抹平成一样高 ← 你踩到的 |
| 肤色 | **冻结（必填）** | 肤色漂移 |
| 服饰 | **冻结（默认）** | **乱生成服饰** ← 你踩到的 |
| 配饰 / 道具 | **冻结（默认）** | 随机出现 / 消失 |
| 表情 / 动作 / 姿势 | **逐格声明（必填）** | 呆滞、重复 |
| 地点 / 光线 / 时间 | 逐格声明 | 场景乱跳 |
| 背景细节 | 自由 | 无所谓 |
| 构图 / 景别 | 自由 | 无所谓 |

### 6.2 服饰 / 配饰的特判

它们是"半固定"属性，最容易留空，单独给一条规则：

- **默认冻结**：剧情不涉及换装 → 直接进 `##固定部分`。
- **必须写死细节**：颜色 / 领结 / 裙型都要写。只写 `school_uniform` 这类"类型"标签不够——模型会自由补颜色，一到光线变化大的 `sunset` 就被重画。
- **换装类剧情才转逐格**：命中"换装 / 试穿 / 更衣 / 换上新衣"等意图 → 转"逐格声明"，
  且**每一格都要写明当前服饰**（第 1 格旧衣、第 2 格换衣中、第 3 格新衣…），
  不能只在"变化的那一格"写。

> 与"禁止重复固定项"的关系：**在固定块里的**属性，动态段禁止重复；
> **不在固定块里的**（即逐格声明项），动态段**允许且必须**每格重复。两者不冲突。

### 6.3 必填清单（校验落点）

`##固定部分` 必须至少包含以下标签，缺任一项 → 判不合格，回炉：

1. 人数 / 性别（`1girl` 或 `2girls` …）
2. 发色
3. 发型
4. 瞳色
5. 体型 **和** 肤色（两者都要；**多人时每个角色都要写全**）
6. **多人时**：身高差关系标签（`height_difference`，更强用 `size_difference`）——否则对称构图会把两人抹平成一样高

服饰 / 配饰不在必填清单里，但**必须被显式归位**——要么在固定块，要么每格动态段写。
校验：若固定块无服饰标签，且某格动态段也无服饰标签 → 判不合格。

### 6.4 多人的额外风险

多人时"逐格声明"的服饰没法用 booru 精确绑定到某个人。缓解办法：

- 角色块顺序全程冻结，动态段的服饰标签按同一顺序排列（角色1 的服饰在前）；
- 方位只能靠标签顺序弱暗示（角色1 的标签排在前）；
- **多人都要换装 = 高风险**，建议在路由层就劝用户拆成多格，或改为"只有主角换装"。

**多人换装的动态段写法（硬性，10 格试衣用例立的规则）**：

每一格的动态段，服饰部分**必须**含以下四项，缺一项判不合格：

| 项 | 内容 | 例 |
|---|---|---|
| ① 角色1 当前服饰 | 写全：类型 + 颜色 | `denim_jacket, white_shirt, black_skirt` |
| ② 角色2 当前服饰 | 同上 | `pink_sweater, plaid_skirt` |
| ③ 换装动作（有换装时） | 拿/换的动作 | `holding_clothes, red_dress` |
| ④ 不变的服饰件 | 放固定块，动态不重复 | `white_socks`（全局）、`hair_ribbon`（角色2） |

附加三条：

- **顺序冻结**：角色1 的服饰恒在角色2 之前；顺序一变，模型可能把两人衣服对调。
- **类型错开**：两人尽量用**不同服装类型**（一个连衣裙、一个上衣+裙），颜色也错开——
  类型差异是给模型的第二重区分线索，光靠颜色容易混。
- **换装节拍错开**：别让两人同一格一起换（"同款不同色"是最小区分测试，风险最高）；
  错开节拍（角色1 先换、角色2 后换）才看得出模型有没有搞混。

> 对照用例：`docs/测试用例-双人试衣-服装店.md`。

**⚠ 实测反例（2026-10-08）：上面这套写法跑 10 格，服饰归属全崩**——连"原装"的第 1 格都上衣互换。

结论：**"靠标签顺序弱暗示绑定"不成立**。两人服饰不同时，booru 无法把人绑到衣服上。
上一轮"牵手拥抱"能过，是因为两人**穿同一套校服**（共有服饰，无需绑定）；本轮两人**服饰不同**，绑定需求一出现就崩。

→ 多人换装的可行解只剩两条，**待 A/B 验证**：

1. **只让一人换装**（方案 A，推荐）：配角服饰进固定块，主角服饰逐格——把"两组不同服饰"降成"一组变、一组不变"。
   **关键细节**：配角的服饰要写进**配角自己的块内、紧贴她的外观标签**（`pink_hair, ..., petite, pink_sweater, plaid_skirt`），
   让她在固定块里就是"外观+衣服"绑死的一整块；主角的服饰一律不进固定块，只在动态段逐格写。
   对照用例：`docs/测试用例-双人试衣-单人换装.md`。
2. **锚点+服饰相邻**（方案 B）：每格把服饰紧贴该角色锚点写（`black_hair, red_dress` / `pink_hair, yellow_dress`），
   只重复锚点这一个标签，给模型绑定线索。A 若仍失败，再叠加 B。

**⚠ 方案 A 实测（2026-10-08）：仍在串，但抓到位置效应。** 只有角色1 换装，结果角色1 试的裙子
**几乎全部落在角色2 身上**（角色2 是组装顺序里紧邻动态段的那一块）。

→ **位置规则（强规律，待最终验证）**：动态段里的服饰会被**紧邻其前的那个角色块**吸收。
即"谁挨着动态段，谁就吃掉动态里的衣服"。

- **通用修法**：**动态段里描述的服饰属于谁，谁的块就必须排在最后。**
- 单换装场景 → `全局 + 配角(冻结) + 主角(换装) + 动态[主角服饰]`。
- 这也解释了 v1（两人都换装）为什么乱：动态段混了两人服饰，却只挨着最后一块，角色1 的服饰没有"归属位置"。
- 对照用例：`docs/测试用例-双人试衣-单人换装.md` §九。

**⚠ v3 重排实测（2026-10-08）**：换装者置后后归属**基本稳住**（10 格 9 格正确）→ 位置规则成立。
剩余 1 格破口是**双马尾形态漂移**，根因是固定块里泛化父标签 `twintails` 与具体款 `low_twintails` 并存（见 §4.1）。

**"两人同款不同色"也不安全**：本用例第 9–10 格（同款条纹毛衣、只差裙子颜色）同样崩了。
路由层遇到"多人 + 换装"，建议直接劝用户拆成多个单人任务。

## 9. 编剧提示词改造（相对现有 `comic_writer`）

现有 `_SYSTEM_PROMPT_TMPL` 是"每格原样重复角色标签"；新契约要改成"固定写一次 + 每格只写增量"。
建议的系统提示词骨架：

```
你是条漫分镜编剧。把用户给的设定写成一份**程序可直接解析**的剧本。
严格照抄下面的结构输出，不要加任何解释、前言、后记，也不要加代码块围栏：

##元数据
数量: {N} | 画风: {style} | 场景: <一句话场景类型> | 人数: <1|2> | 边界: <关键项归属，如 服饰→动态>

##固定部分
<单人：一段英文 booru 标签串，逗号分隔：跨全部 N 格都不变的东西——角色外观，
 以及判定为"不变"的服饰>
<多人：拆成 ##全局 / ##角色1 / ##角色2 …，每块一个唯一锚点>

##动态部分
---
<第 1 格：只写相对固定块的增量——动作、表情、地点、光线、构图>
---
<第 2 格：...>
---
（共 {N} 段，用 --- 分隔）

硬性要求：
1. 所有正文块必须是 danbooru 英文标签：全小写、下划线连接、逗号分隔、不是句子，
   绝对不许出现中文、冠词或标点句读。
2. `##动态部分` 必须正好 {N} 段，用 `---` 分隔。
3. 每段动态只写增量，不许重复 `##固定部分` 已有的属性（重复会导致角色漂移）。
4. 边界判定：这 N 格里不变的 → 固定；随剧情变的 → 动态。
   如果剧情本身就在改变某个属性（如换装），那个属性必须放进动态，不许留在固定部分。
5. 多人（人数 ≥2）：固定部分按角色分块；每块一个唯一锚点且互不相同；角色块顺序全程不变；
   删掉 solo；人数标签只写在 ##全局；动态段只写互动与方位，不碰外观。
6. **属性不许留空**（见下）：
   - 固定部分必须含：人数/性别、发色、发型、瞳色、体型或肤色；
   - 服饰 / 配饰必须显式归位——要么进固定块，要么每一格动态段都写当前值；
   - 表情 / 动作 / 地点 / 光线：每格都要写。
7. 换装类剧情：服饰转"逐格声明"，每一格都要写明当前服饰，不能只在变化的那格写。
8. 剧情节奏：{pacing}
9. 不要写任何解释、编号说明或代码块围栏。
```

校验层在现有基础上新增以下检查：

1. 段数是否等于 N；
2. `##固定部分` 是否为空；
3. 固定 ↔ 动态是否冲突（固定写了"红裙"、动态又写"换上蓝裙"）；
4. 动态段是否重复固定项；
5. **标签形态**：正文块是否含中文 / 句子成分 / 大写（§4）；
6. **多人**：人数 ≥2 时是否有唯一锚点、是否残留 `solo`；
7. **必填清单**：固定部分是否含 §6.3 的五项；
8. **不留空**：服饰 / 配饰是否被显式归位（固定块，或每格动态段）。

## 10. 待定 / 风险

- **超出 10 张怎么办**：默认阈值 10（≈1 分钟）。用户明确要更多时，建议**内部分批（每批 ≤10）+ 对外一次性返回**，
  并设一个硬上限（建议 30）防滥用。**需拍板**：是"直接拒绝"还是"分批跑"。
- **服饰默认归属**：本条定为"默认冻结、仅换装转逐格"。若实际测试中仍有乱穿衣，可考虑把服饰也列进必填清单。**需观察**。
- **是否加气泡**：连续漫画若走 `--silver-only`（无气泡），契约不需要 `气泡:`；
  若要气泡，`##动态部分` 每段要多一个气泡字段（气泡是中文，不进 danbooru 校验）。**需拍板**。
- **固定块是否回显确认**：提外观版的标签要不要先回显给用户确认再跑（QQ 多一轮交互）。
- **词表**：漫画词 / 画风词的最终清单；`qwen漫画` 是否与 `silver漫画` 同流水线（只换渲染渠道）。
- **旧契约怎么办**：新契约只覆盖连续漫画；旧的"silver + qwen 加气泡"分格流程是否保留原 `script.md` 格式。

## 11. danbooru 标签规则补充（2026-10-08 调研）

> 出处：danbooru / safebooru wiki、BUR 论坛。仅记与"固定+动态"契约相关的硬规则。

### 11.1 标签分类：哪些能进提示词

| 类别 | 例 | 进提示词？ |
|---|---|---|
| general | `1girl` `blue_hair` `sitting` | ✅ |
| character | `hatsune_miku` | ✅ 指定角色；自带外观，串味最低 |
| copyright | `touhou` `vocaloid` | ✅ 指定系列 |
| artist | `kantoku` | ⚠️ 带画师风格；不要就放**反向词** |
| meta | `highres` `absurdres` `commentary` `watermark` `bad_id` | ❌ 会画水印/文字/伪影 |

- `rating:general` 这类是**搜索运算符**，不是普通标签，别直接写进提示词。
  （社区 anime 模型把 `safe`/`nsfw` 当训练标签，可作安全控制词，正反都写。）
- ⚠ 我们的 `base_prompt` 含 `absurdres`——它属 **meta 类**。社区常拿它当质量词，但严格说它描述"原图分辨率"，有触发伪影风险。**待 A/B**。

### 11.2 计数 / 关系标签硬规则

- `1girl` = "至少一名女性"，**不保证只有一人**；`solo` 才是"画面只有一个人"。
- **`solo` 与 `2girls` 直接矛盾** → 多人必须删 `solo`（§5.2 第 3 条已如此）。
- `duo` **已弃用**，不要用；两人写 `2girls`。
- 互动标签：
  - `holding_hands` = 互相握手；`interlocked_fingers` = 十指扣，**须同时写 `holding_hands`**；
  - `hugging` 已 alias 到 `hug`，写哪个都行；
  - **`looking_at_another` 是单向**（A 看 B）；**互相看要用 `looking_at_each_other`**；`eye_contact` = 对视眼睛；
  - 搂肩区分：`arm_around_shoulder`（环抱）、`arm_on_another's_shoulder`（搁肩）、`hand_on_another's_shoulder`（单手放肩）——
    **撇号 `'s` 不能漏**，漏了语义变成"放自己身上"。
- `height_difference` = 自然身高差；`size_difference` = 夸张体型差（giantess / minigirl）→ 我们用前者，正确。

### 11.3 构图 / 视角 / 景别

**白名单**（danbooru wiki 收录，放心用）：
- 景别：`full_body` `upper_body` `cowboy_shot`(脸到大腿) `portrait`(脸到肩) `wide_shot` `feet_out_of_frame` `cropped_legs` `head_out_of_frame`
- 视角：`from_side` `from_behind` `from_above` `from_below` `from_outside`
- 视线：`looking_at_viewer` `looking_back` `looking_down` `looking_up` `turning_head`（`looking_away` 标 Ambiguous，尽量换具体方向）

**灰名单**（未在 danbooru wiki 找到，但我们正在用）：
- `medium_shot`、`close-up` —— **没有 wiki 页**，但实测能出图（模型从非 booru 语料学到）。
  追求 danbooru 语义精确时，`medium_shot` → `cowboy_shot` / `upper_body` / `portrait`；
  `close-up` 无对应 booru 标签，**保留**（模型认识，实测正常）。
- `front_view` / `back_view` / `side_view` 是自然语言写法 → 一律用 `from_*` 系列。

### 11.4 别名与弃用

- 别名（写旧名会被重定向，建议直接用主名）：`twin_tails`→`twintails`、`hugging`→`hug`、`gray_hair`→`grey_hair`、`clavicle`→`collarbone`。
- `height_difference` 曾被提议弃用（理由：充斥微小身高差），**BUR 被驳回，仍然有效**。
- 查询：`/wiki_pages/<标签>`；弃用查论坛 `deprecate <tag>` 或 `/bulk_update_requests`。

### 11.5 提示词顺序（社区共识）

danbooru 站内标签无序；但出图模型**靠前的标签权重更高**。建议：
`质量词 → 人数 → 角色/系列 → 外观 → 服饰 → 动作/互动 → 背景/光线 → 景别`
我们的组装 `全局 + 角色1 + 角色2 + 动态[i]` 与此一致（人数/外观在前，动作/背景在后）。

### 11.6 对现有契约的修订点

1. §5.2 第 4 条"互动标签"补：**互相看用 `looking_at_each_other`，单向看用 `looking_at_another`**。
2. 测试用例第 8 格（面对面）现用 `looking_at_another` → 建议改 `looking_at_each_other`。
3. `base_prompt` 的 `absurdres` 待 A/B。
4. `medium_shot` 保留（实测可用）；若要 danbooru 精确，改 `cowboy_shot`。
