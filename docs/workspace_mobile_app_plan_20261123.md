# 整合工作台 UI 方案 v2：手机 App 方向的网页（2026-11-23）

> 本文是 `workspace_ui_plan_20261123.md` 的细化，不推翻它。v1 定的是「整合哪些功能、结果优先、明暗主题」；v2 回答「按手机 App 方向做网页，骨架和技术形态怎么定」。

## 0. v1 与 v2 的差别

| | v1（响应式网页） | v2（移动优先 Web App） |
| --- | --- | --- |
| 起点 | 桌面页缩小到手机 | 手机页拉宽到桌面 |
| 导航 | 点链接换页，靠浏览器后退 | 页面栈 push/pop，左滑返回，tab 是根 |
| 形态 | 浏览器标签页，有地址栏 | PWA：可加主屏、standalone 全屏、离线壳 |
| 手势 | 无 | 右滑返回、下拉刷新、看图缩放、tab 双击回顶 |
| 安全区 | 无 | `safe-area-inset`、`100dvh`、禁双击缩放 |
| 首屏 | 功能入口列表 | 工作台：任务状态 + 接着做 |

一句话：**v1 是「网页适配手机」，v2 是「手机 App 刚好跑在浏览器里」。**

## 0.1 已拍板（2026-11-23）

- 形态：**PWA**（加主屏 / 全屏 / 离线壳）。
- 顺序：**手机优先**；桌面宽屏适配往后放，不阻塞首期。
- 首期：**先壳 + 工作台**，不上漫画结果页。
- 本轮**不写业务代码**，先把结构类型定死。

## 1. 定位与美学方向

沿用 v1 的定位：一个人用的创作结果台，打开就是结果，改哪一页就说哪一句。

美学方向定为**编辑式克制（editorial restraint）**，不是泛泛的「简洁现代」：

- 图是唯一主角，界面元素退到细线、留白和小字；
- 系统字体（移动端跟平台原生，桌面跟系统），不引入第三方展示字体；
- 一个强调色，只用在主按钮和当前状态，其余全是中性；
- 不用毛玻璃、发光、渐变按钮、大圆角卡片套卡片；
- 动效只做两件：页面转场、状态变化。

反面清单（照抄即失败）：万物皆卡片、居中一切、默认深色 + 霓虹点缀、参数平铺、剧本默认展开、向导式教程感。

## 2. 技术形态：PWA

| 方案 | 好处 | 代价 | 结论 |
| --- | --- | --- | --- |
| 普通响应式网页 | 改动最小 | 有地址栏、不能加主屏、无离线壳，App 感弱 | 否 |
| **PWA（推荐）** | 加主屏、standalone 全屏、离线壳、推送能力预留 | 需 manifest + service worker；iOS 安装要 https | **是** |
| Capacitor 打包原生 | 最像 App，能进应用商店 | 要原生构建链、签名、审核，远超「整合网页」 | 否 |

PWA 的最小落地物：

```
web_workspace/
  manifest.webmanifest      名称、图标、display: standalone、theme_color
  sw.js                     只缓存静态壳，不缓存 API 结果（避免看到旧图）
  index.html                首屏内联主题脚本，刷新无闪色
```

约束：localhost 和 https 下 PWA 完整可用；手机用局域网 `http://IP:5174` 访问时，安卓浏览器仍可「添加到主屏」但没有离线壳；iOS Safari 必须 https 才能加主屏。现在隧道是 https，真机验证走隧道即可。

## 3. App 骨架（与网页最大的差别）

### 3.1 页面栈

- 5 个 tab 是 5 个独立的栈根；点进详情 = push，返回 = pop；切 tab 不销毁原栈。
- 路由：`/workspace#/discover` → `#/comic/3`（漫画第 3 页）→ 返回回 `#/comic`。浏览器前进后退仍可用。
- 转场：push 从右滑入（`translateX(100%)→0`），pop 反向；180ms `ease-out-quart`。`prefers-reduced-motion` 下直接切换。
- 只维护一个 DOM 栈容器，不做「每页一个 iframe 叠着」——那样手势和滚动会打架。

### 3.2 底部 tab

五个槽位：**工作台 / 画廊 / 〔创作〕/ 漫画 / 角色**。正中间是凸起的创作按钮，不是页面 tab。

- 常驻 56px + `env(safe-area-inset-bottom)`，图标 20px，文字 10px，触控区 ≥44px；
- 中间创作按钮 46px 圆形凸起 20px，点击弹出 bottom sheet，不是切页；
- 双击当前 tab = 回到该栈顶部（App 标配，网页里没有）；
- 漫画台与 MOSS 共用一个「漫画」槽，进去后顶栏下方两段切换，两套任务状态独立；
- 生图不再单独占一格，收进创作抽屉里作为一个工具选项。

### 3.3 手势

| 手势 | 作用 | 边界 |
| --- | --- | --- |
| 左边缘右滑 | 返回上一层 | 根页不响应；输入框聚焦时不抢 |
| 下拉 | 刷新当前结果列表 | 只在滚动到顶时触发，避免和看图冲突 |
| 双指缩放 / 双击 | 看大图 | 只在大图查看器里启用 |
| 长按卡片 | 出操作菜单 | 不覆盖「点开」行为 |

### 3.4 移动端硬约束

`viewport-fit=cover` · `height:100dvh` · `user-scalable=no`（图形界面不需要页面缩放）· `-webkit-tap-highlight-color:transparent` · `overscroll-behavior:contain` · 所有可点区域 ≥44px。

## 4. 五个模块在 App 里怎么落位

| 模块 | 在 App 里的角色 | 首期做法 |
| --- | --- | --- |
| 工作台 | 首页，看「任务进行到哪」+ 接着做 | 新写（见 §5） |
| 画廊 | 作品归档，只看完成的图 | 复用已有 API，新写视图层 |
| 创作（中间按钮） | 一句话 + 选工具，发起新任务 | bottom sheet，见 §5.2 |
| 漫画 / MOSS | 结果优先，核心差异 | 新写结果视图，只复用 API（见 §6） |
| 角色 | 对话式，输入吸底，最像 IM | 复用 `/api/persona/*`，新写视图 |

不做全 iframe：页面栈 + 手势 + 统一转场需要控制 DOM，iframe 的双层滚动与手势冲突无法靠桥接完全消除。v1 里的「过渡期 iframe」在 v2 降为应急手段，不作为目标形态。

## 5. 工作台与创作（解决「画廊 vs 发现页」冲突）

### 5.1 冲突的根因

豆包的发现页是「看别人的模板 → 点一下用同款」，它成立的前提是每条作品都带**完整提示词 + 作者 + 使用量**。我们这边生成完只留下图和任务记录，**拿不到可复用的完整提示词**（剧本、LoRA、参数散在任务 payload 里，且不是给终端用户复刻用的）。所以照搬豆包发现页 = 把画廊换个地方再摆一遍，两个页面抢同一件事。

解法是**按「任务状态」和「作品归档」切分，不按「新旧」切分**：

| | 工作台 | 画廊 |
| --- | --- | --- |
| 回答的问题 | 我现在有哪些活在进行、接着做哪个 | 我以前出的图，按来源找出来看 |
| 内容 | 进行中的队列（带进度）+ 最近任务（可续） | 已完成的作品，三来源切换、看图/隐藏 |
| 卡片 | 任务名 + 状态 + 进度条 | 缩略图 + 来源 · 时间 |
| 不放 | 纯作品图墙 | 队列、进度 |

两页不再互为副本：工作台不想看剧透只关心进度，画廊不关心任务只关心图。

### 5.2 工作台结构（自上而下）

1. 顶栏：标题「工作台」+ 主题开关；
2. 「进行中」：任务名 + 状态词（`生成中 3/8` / `排队 2`）+ 3px 进度条；有失败项时卡内一行原因 + 重试，不做红色警告墙；
3. 「接着做」：最近两列任务卡（缩略图 + 任务名 + 来源 · 页数），点进对应结果页续做；
4. 底部 tab 常驻。

数据只用现有接口：漫画取 `/api/comic/tasks`，生图取 `/api/gen/history`，画廊取现有列表接口；MOSS 没有列表口就 `localStorage` 记 id 再查 `/api/moss/status`，不新建后端。

### 5.3 创作抽屉（中间凸起按钮）

点击底部中间创作按钮 → bottom sheet 从下方升起：

1. 一句话输入框（占位「描述你想创作的内容…」，多行，右下角发送圆钮）；
2. 三个工具选一个：**生图 / 漫画 / 角色**；
3. 发送后带这句话跳到对应模块并预填，抽屉关闭。

不放：提示词输入、参数、LoRA 选择、画风选择、seed。这些都留在各自模块或专家层里，创作入口只负责「把一句话收下来并分流」。

### 5.4 数据来源限制带来的取舍

既然拿不到完整提示词，所有卡片一律不放提示词片段、作者、使用人数、点赞收藏——这些在豆包成立是因为它有共享模板生态，我们没有。首页只放我们自己真实有的事实：任务名、状态、进度、来源、时间。

## 6. 漫画 / MOSS 结果优先页（核心）

阶段从三步压成两步：**写一句话 → 看结果**。没有独立的「看剧本」页。

### 状态机

```
无任务 ──写一句话/生成──> 生成中 ──成功──> 结果页 ──每页反馈/补正──> 该页补正中 ──成功──> 该页 v2
                            └─失败──> 卡内原因 + 重试
```

### 结果页元素（每页只有四样）

- 大图：按原比例完整显示，不裁切；左上页码 `03`，右上状态词；
- 状态词：`待生成 / 排队 / 生成中 / 已完成 / 补正中 / 失败`；
- 反馈输入框：占位「这页哪里不对，直接说…」；
- 动作：空输入显示「重画」，有字显示「补正重画」。

页码横条在顶栏下方，当前页高亮；上下页用左右滑切换（与返回手势区分：返回只在左边缘 20px 内）。

### 不显示（默认屏）

剧本正文、分镜表、提示词、seed、LoRA、气泡参数、修改历史。全部收进右上角专家开关 → 桌面右侧抽屉 / 手机底部抽屉，默认关，只读 + 一键复制。

### 反馈闭环

提交 → 该页「补正中」→ 补正 AI 拿当前页 layout + prompt + 角色外形 + 用户这句话 → 只重画这一页 → 回「已完成」并标 `v2`。其他页不动、不滚动跳动。复用现有 `/api/comic/fix`、`chat_revise`、`rerender`；MOSS 缺按页补正口就做薄适配（反馈写入该页 payload 再重画），不改生成链。

验收：默认屏搜不到「剧本 / 提示词」字样；三次点击内完成 生成 → 反馈 → 重画；单页重画后其他页图不刷新。

## 7. 主题与视觉 token

继承 P0 画廊的 `data-theme` 语义变量，直接上移为全局 token：

| Token | 白天 | 黑夜 |
| --- | --- | --- |
| `--bg` | `#f5f6f8` | `#0c0d10` |
| `--card` | `#ffffff` | `#171a20` |
| `--line / --line-soft` | `#dfe3ea / #e9ecf1` | `#2a2f39 / #20242c` |
| `--tx / --dim / --mute` | `#1b1e24 / #67707e / #929aa6` | `#f2f3f7 / #9aa0ad / #6e7482` |
| `--accent` | `#c62e5b` | `#ff5c8a` |
| `--success / --warn / --error` | `#15803d / #b45309 / #c62828` | `#4ade80 / #fbbf24 / #f87171` |

避免纯黑纯白；中性色略偏冷，和强调粉拉开。主题在 `<head>` 内联脚本先落地，刷新无闪色；壳是唯一开关（写 `workspace_theme`），其他视图跟随。

尺寸：卡片圆角 16 / 按钮与输入框 10 / chip 999；间距 8/12/16/24；字号 12 灰字 / 13 chip / 14 正文 / 16 标题 / 20 页标题；只用 400 和 500 两档字重。

四种状态：空态 = 单色线性图标 + 一句话 + 一个主按钮（不用插画）；加载 = 同尺寸同圆角骨架卡 + shimmer；错误 = 卡内一行原因 + 重试，全局 toast 只报成功/失败且 3 秒消失；禁用 = 透明度 0.5，不改色相。

## 8. 桌面表现

桌面不是另一套 UI，是同一套的宽屏版：手机宽度的卡片流在桌面变成多列，底部 tab 收成左侧 72px rail，专家抽屉从底部改到右侧 360px。任务状态、页码、反馈入口的位置不变。这样不会维护两套界面。

## 9. 分期与验收

| 期 | 内容 | 验收点 |
| --- | --- | --- |
| P0 壳 + 工作台（首期） | `/workspace`、manifest/sw、页面栈、底部五格（中间创作凸起）、主题、安全区、工作台两区块、创作抽屉 | 手机加主屏后 standalone 全屏；创作按钮弹抽屉且能分流到三模块；工作台只显示任务状态不显示作品墙；右滑返回可用；主题刷新保持 |
| P1 漫画结果优先 | 两步流程、按页卡片、反馈 → 补正 → 单页重画、专家抽屉 | 默认屏搜不到剧本/提示词；三次点击走完；单页重画不影响其他页；旧路由仍可用 |
| P2 画廊/角色接入 | 画廊归档视图、角色对话视图、手势与状态统一 | 五模块主题一致；原 API 与守卫测试全绿；无双层滚动条 |
| P3 桌面宽屏 | rail + 多列 + 右侧专家抽屉 | 同一套 UI 拉宽，不维护第二套 |

明确排除：管理页、状态页、小说、showcase、社区化功能。
