# 整合工作台 UI 设计方案 v1（2026-11-23）

## 0. 范围与基线

只整合五个功能：画廊、跑图台、漫画工作台、MOSS 漫画、角色扮演。管理页、状态页、小说、showcase 不进新壳。

豆包截图只借三样东西：**两列圆角结果卡、底部能力 chip、一句话输入框**。不照抄作者头像、使用人数、推荐算法、语音和加号——我们目前没有对应的真实能力，放了就是空按钮。

沿用已有原则：结果优先 / 三层信息 / 少字 / 明暗双主题。P0 画廊的 `data-theme` 语义色变量直接上移为全局 token。

新入口定为 `/workspace`，旧五条路由和全部 `/api/*` 不动，随时可回退。

## 1. 定位

**这不是功能入口合集，是一个人用的创作结果台。打开就看到最近出的图，哪一页不对就地改，不经过剧本和参数。**

一句话产品感：**打开就是结果，改哪一页就说哪一句。**

反面清单：不做向导式教程感；不默认展示剧本正文；不参数平铺；不做功能说明书式首页。

## 2. 信息架构

### 桌面端（≥1024px）

- 左侧 72px 图标 rail，hover 展开到 200px：发现 / 画廊 / 跑图 / 漫画 / 角色。
- 顶栏 64px：返回、任务名 + 进度胶囊、主题开关、专家抽屉开关（仅漫画/跑图出现）。
- 内容区最大宽 1440，左右留白 24；iframe 页满高自适应，不出现第二条滚动条。

### 手机端（<768px）

- 顶栏 56px sticky：标题 + 状态胶囊 + 主题开关。
- 内容区左右留白 16；发现页两列卡片，其余单列。
- 底部 tab 五等分：发现 / 画廊 / 跑图 / 漫画 / 角色，56px + 安全区，触控目标 44px。

### 五个功能怎么落位

**漫画工作台与 MOSS 共用一个「漫画」槽位**，进入后顶栏下方两段切换：`漫画台 | MOSS`。两套任务状态和接口独立，共用同一个结果优先视图壳；用户不必在首页先决定用哪个引擎。

路由：`/workspace#/discover|gallery|gen|comic|persona`，漫画内 `?engine=comic|moss`。浏览器前进后退可用。桌面快捷键：`1–5` 切模块，`/` 聚焦输入框，`Esc` 关专家抽屉。

## 3. 发现页

桌面骨架：左侧 rail；右侧从上到下是标题 + 主题、筛选 chip（全部 / 漫画 / MOSS / 跑图 / 画廊）、两列以上结果卡、底部能力 chip + 输入框。

手机端同结构：卡片两列、间距 12，chip 横滑，输入框吸底在 tab 之上。

### 卡片里放什么

| 放 | 不放 |
| --- | --- |
| 4:5 缩略图 | 作者头像、昵称、粉丝数 |
| 任务名，最多 14 字，超出省略 | 「765 人使用」这类社交证明 |
| 一行灰字：`8 页 · 昨天 21:14` | 提示词、剧本片段、LoRA 名 |
| 整卡可点，直达任务 | 标签墙、点赞、收藏、更多菜单 |

排序按最近修改倒序，默认 12 张 + 「查看全部」。筛选是一排 chip，不是 tab 页。

数据源只用现有接口：漫画取 `/api/comic/tasks`，跑图取 `/api/gen/history`，画廊取现有列表接口。MOSS 若没有列表接口，用 localStorage 记最近任务 id 再查 `/api/moss/status`，**不新建后端**。

### 底部 chip 与输入框

五个 chip 只写动作：画廊 / 跑图 / 漫画 / MOSS / 角色，44px 高。输入框占位「写一句话，选个工具开工」，右侧箭头；输入后出现「生成图片」「做成漫画」两个动作，带文字跳到对应模块并预填。

## 4. 统一页壳与结果优先视图

### 页壳

```
顶栏：返回 · 任务名/进度 · 主题 · 专家（按需）
二级：漫画台|MOSS 切换，或跑图队列状态
主体：一句话输入条（仅无任务时） + 结果区（默认占屏 90%）
专家抽屉：桌面右侧 360px / 手机 bottom sheet，默认关
```

每页只有一个主按钮，用唯一强调色；其余全是中性描边按钮。画廊、跑图、角色首期以 iframe 接入，壳负责导航、主题、状态；iframe 内原页顶部外链由桥接收起，不出现双层顶栏。

### 漫画 / MOSS 的核心改法

阶段从三步压成两步：**写一句话 → 看结果**。取消独立的「看剧本」步骤。

1. 未开任务：一张输入卡，两行 textarea，占位「写一句剧情，AI 来写剧本」，一个「生成」按钮，零参数。
2. 结果区：桌面左侧 56px 页码条 + 两列大图；手机顶部 48px 横向页码条 + 单列大图。每页卡片只有四样：
   - 图，按原比例完整显示，不裁切；
   - 左上页码 `03`，右上状态词：`待生成 / 排队 / 生成中 / 已完成 / 补正中 / 失败`；
   - 一行反馈输入框，占位「这页哪里不对，直接说」；
   - 一个动作按钮：空输入显示「重画」，有字显示「补正并重画」。
3. 不显示：剧本正文、分镜表、提示词、seed、LoRA 标签、气泡参数、修改历史。
4. 反馈闭环：提交 → 该页进入「补正中」→ 补正 AI 拿当前页 layout + prompt + 角色外形 + 用户这句话 → **只重画这一页** → 状态回「已完成」，角标 `v2`。其他页不动、不滚动跳动。复用现有 `/api/comic/fix`、`chat_revise`、`rerender` 一路接口；MOSS 若缺按页补正口，先做「反馈写入该页 payload 再重画」的薄适配，不改生成链。
5. 批量：顶部只留「全部出图」；失败页在卡内显示一行原因 +「重试」，不开红色警告墙。
6. 专家抽屉：剧本全文、分镜表、提示词、角色/LoRA、seed、补正记录（只读时间线）、一键复制。默认关，打开不挤压结果区。

验收：默认屏搜不到「剧本/提示词」字样；三次点击内完成生成 → 反馈 → 重画；单页重画后其他页图不刷新。

## 5. 组件与视觉规则

### 色板

继承 P0 变量，补语义色：

| Token | 白天 | 黑夜 |
| --- | --- | --- |
| `--bg` | `#f5f6f8` | `#0c0d10` |
| `--card` | `#ffffff` | `#171a20` |
| `--card2` | `#eef1f5` | `#20242c` |
| `--line / --line-soft` | `#dfe3ea / #e9ecf1` | `#2a2f39 / #20242c` |
| `--tx / --dim / --mute` | `#1b1e24 / #67707e / #929aa6` | `#f2f3f7 / #9aa0ad / #6e7482` |
| `--accent` | `#c62e5b` | `#ff5c8a` |
| `--success / --warn / --error` | `#15803d / #b45309 / #c62828` | `#4ade80 / #fbbf24 / #f87171` |
| `--shadow` | `0 4px 16px rgba(24,32,48,.06)` | `0 8px 24px rgba(0,0,0,.35)` |

装饰用亮粉保留 P0 的 `#e0456f / #ff5c8a`，文字与按钮用上表 `--accent`，保证白天模式对比度。

### 尺寸

- 圆角：卡片 16 / 按钮与输入框 10 / chip 999 / 抽屉上角 20 / 缩略图 8。
- 间距：4px 基准，8 / 12 / 16 / 24 / 32；卡间距桌面 16、手机 12；内容留白桌面 24、手机 16。
- 字号：系统字体栈；12 灰字、13 chip、14 正文、16 卡片标题、20 页标题；字重 400/500/600，行高 1.5，数字等宽。
- 动效：hover 最多抬升 2px，120–180ms；`prefers-reduced-motion` 下全关。

### 四种状态

| 状态 | 规则 |
| --- | --- |
| 空态 | 单色线性图标 40px + 一句话 + 一个主按钮，不用插画 |
| 加载 | 骨架卡同尺寸同圆角，shimmer 1.2s；页级运行用 2px 顶部进度条 + 状态词 |
| 错误 | 卡内一行原因 +「重试」；全局 toast 仅成功/失败，3s 自动消失 |
| 禁用 | 透明度 0.5，不改色相；按钮文字保持动作词 |

无障碍：焦点环 2px `--accent` + 2px offset；触控目标 ≥44px；图片 alt = 任务名 + 页码；主题在 `<head>` 内联脚本先落地，刷新无闪色。

## 6. 技术取舍与文件夹

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 全部 iframe | 最快、零功能回归 | 双层顶栏/滚动条；手机底栏打架；主题逐页同步；漫画去剧本改不了 |
| 全部重写 | 统一组件与主题 | 上万行重写，丢 id / 接口风险高 |
| **新壳 + 分层迁移** | 该重写的重写，该保留的保留 | 过渡期需要主题桥接 |

推荐第三项：画廊、跑图、角色已有守卫与稳定接口，先 iframe；漫画与 MOSS 必须改交互模型，在新壳里重写视图层、只复用 API；导航、主题、状态胶囊收口在壳里。旧路由保留，任何一期出问题都能单期回退。

主题桥接：壳是唯一开关，写 `workspace_theme`；已支持 `data-theme` 的画廊直接跟进，其余页补同名变量 + `postMessage` 监听。

建议新目录（服务挂 `/workspace`，不碰现有 `web/`）：

```
web_workspace/
  index.html
  styles/
    tokens.css
    base.css
    components.css
  src/
    shell.js
    api.js
    views/
      discover.js
      comic.js
      gallery.js / gen.js / persona.js
  assets/icons/
  docs/mapping.md
  tests/shell.spec.js
```

`docs/mapping.md` 是必交物：迁移前把老页 id 和接口列清，逐期勾掉，确保「不丢任何现有功能」。

## 7. 分期与验收

| 期 | 内容 | 验收点 |
| --- | --- | --- |
| P1 新壳 + 发现页 | `/workspace`、五槽导航、两列结果卡、chip + 输入框、明暗切换 | 五个入口都可达；卡片只有图/标题/一行灰字；主题刷新保持；无双层滚动条 |
| P2 漫画 / MOSS 结果优先 | 两步流程、按页卡片、反馈 → 补正 → 单页重画、专家抽屉 | 默认屏看不到剧本/提示词；三次点击走完流程；单页重画不影响其他页；旧路由仍可用 |
| P3 存量接入 + 组件沉淀 | 画廊/跑图/角色 iframe 接入；token 与组件单源；按 mapping 去 iframe | 主题跨五模块一致；原功能 id / 接口 / 守卫测试全绿 |

明确排除：管理页、状态页、小说、showcase、社区化功能。
